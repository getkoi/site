Install the project-agnostic skill:

```bash
npx skills add getkoi/junji
```

Path: [`skills/junji/SKILL.md`](https://github.com/getkoi/junji/blob/main/skills/junji/SKILL.md). Invoke `/junji <verb>` in your coding agent; the [guide](/junji/docs/guide) walks through each verb. The skill saves the plan and progress under `.koi/run/` and executes one phase at a time with `next`.

## Dispatch

- No active effort in `.koi/board.json` → `begin` (legacy backlogs require explicit migration).
- Explicit `/junji connect` → optional Jira connection review after backlog acceptance; Next action stays unchanged.
- “Do the next task” → `next`.
- Otherwise, consult the active board effort’s `next_action`.

The skill loads its per-verb instructions only as needed. It owns the method files and documents runnable verification commands during `plan`. It requires the standalone `junji-board` binary, but no Yokai executable, sensor scripts, model tiers or sandbox configuration. It does not manage driver config, ledger, or recovery artifacts. The [method's source vocabulary](https://github.com/getkoi/junji/blob/main/skills/junji/CONTEXT.md) defines the on-disk contract.

`connect` delegates Jira discovery and publication through the host's official Atlassian Jira MCP
with host-managed OAuth. Supply a board URL and approve an exact readable summary, including the
publishing host and named server, not configuration JSON. That identity stays pinned independently
of coding candidates and model tiers. ACP does not guarantee OAuth reuse or host-config inheritance;
an unavailable named server fails explicitly rather than copying credentials or switching providers.
Koi owns no Jira login or credentials. Use the host's MCP/OAuth UI for interactive sign-in; headless
auth stays pending while local execution continues. The runtime retains local authorization, proofs,
requests and bindings; coding phase agents never call Jira tools. Direct MCP trusts the host/agent.
Require agent-reported actual remote readbacks, not narrative success or an independent runtime audit.
[Jira visibility](/yokai/docs/visibility) separates saved setup from verified delivery.

For later sensor changes and sandbox image recipes, use the [yokai helper skill](/yokai/docs/skill). To run prepared phases unattended, use the [yokai driver](/yokai/docs/run).
