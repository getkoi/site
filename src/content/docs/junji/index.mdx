Use junji (順次) to plan work that spans several agent sessions. The method skill saves the plan, backlog, and decisions under `.koi/run/`, so another session can continue. Run `/junji next` to complete one phase in your agent, or let [Yokai](/yokai/docs) run the prepared phases unattended. Project state lives under `.koi/`; the skill works across projects.

Install:

```bash
npx skills add getkoi/koi
```

Invoke with `/junji` and an optional verb. Say "do the next task" when the backlog points at `next`.

**junji is not yokai.** The method skill plans one phase and can execute it through `next` in a single agent session. The [yokai driver](/yokai/docs) loops phases unattended and verifies the contract after each one. Both read the same `.koi/run/` files. Folder layout and terms: [Start here](/koi/docs).

## When to use junji

Use junji when the work spans many sessions, each slice should be independently verifiable with an objective gate, and you want plans and position to survive `/compact` or a fresh process.

It works best when fmt, lint, typecheck, and tests can exit 0. Skip it for one-off edits.

## Pipeline

Ten verbs: begin → plan → refine → next ↺ → (iterate → next ↺)* → consolidate, with optional research, design, grill, and brief. Only `next` writes product code. Check **Next action:** at the top of `.koi/run/BACKLOG.md`. Verb-by-verb steps: [Guide](/junji/docs/guide).
