Prepare a project with `/junji begin → plan → refine`, then run Yokai. It consumes the copied
repository documents; the execution machine does not need the Junji skill installed.

## Run and inspect

Bare `yokai` opens missing preparation or enters the cockpit. Press **p** to reopen the wizard;
while a phase runs, preparation waits for its boundary. Review sensors, edit phase rows and manage
the environment there. `/yokai` helper operations remain available.

```bash
yokai --once          # guided missing setup, review checks, then offer to start
yokai                 # reuse settings and continue
yokai doctor --probe  # optional diagnostics
yokai --headless      # requires saved settings and a reviewed gate and current assessments; never onboards
yokai --host          # bypass configured sandbox for this launch
yokai --max-cost 5.00
yokai --max-iters 3
yokai --theme hiru
yokai --allow-gated   # explicit human-gate authorization; standing directives still apply
```

```bash
# Existing legacy configuration:
yokai migrate
# Develop from the framework checkout:
cargo run -p yokai -- doctor --probe
```

## Sensors and settings

Reusable settings live in `.koi/yokai.yml`, with reviewed phase assessments and effort differences in `.koi/run/yokai.yml`.
[Configuration](/yokai/docs/configuration) explains nested inheritance and reviewed phase assessments.

```bash
bash .koi/sensors/30-cargo-test.sh
```

Changing a script or the verification bar requires another interactive review. A valid failing
check remains intact. [Sensors](/yokai/docs/sensors) · [Recipes](/yokai/recipes).

## Sandbox

Run `yokai` to select the backend and image. Build the repo-owned recipe:

```bash
# Apple:
container system start
container build -f .koi/Dockerfile.sandbox -t koi-myproj-sandbox .
# Docker:
docker build -f .koi/Dockerfile.sandbox -t koi-myproj-sandbox .
```

Set the matching `sandbox.image` in `.koi/yokai.yml`. Recreate an existing named sandbox after
rebuilding its image. [Sandbox launch](/yokai/docs/sandbox/launch).
