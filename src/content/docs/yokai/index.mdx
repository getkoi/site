Yokai runs your prepared phases through a coding agent and verifies the results on disk. [Junji](/junji/docs) prepares the project plan and backlog. Yokai writes each phase’s implementation plan, runs it, and shows progress in a terminal UI. The driver owns the prompts for Plan, Build, Seal, and recovery. See [Build](/yokai/docs/build).

Yokai owns its setup, diagnostics and runtime. Junji alone needs no executable. First green run: [Quickstart](/koi/docs/quickstart). Layout and terms: [Start here](/koi/docs).

## Choose your next step

Start with the [quickstart](/koi/docs/quickstart) to verify one phase. Then use [Run](/yokai/docs/run) to continue the effort.

Read [Sessions](/yokai/docs/sessions) to understand fresh context, token savings, and interrupted turns. Read [Swarms](/yokai/docs/swarms) to enable parallel workers.

## What it does

Every phase runs Plan → Build → Seal. After each phase the driver checks the contract on disk: the phase is marked `[done]`, there is a new commit, the gate is green, and the tree is clean. It never trusts the agent's self-report. The driver halts fail-fast for a red gate, stall, gated phase without explicit authorization, cost ceiling, or completion.

## yokai driver vs yokai skill

| | **yokai driver** (binary) | **yokai skill** (coding agent) |
|---|---------------------------|--------------------------------|
| Runs phases | yes — unattended supervisor | no — not a junji verb |
| Owns | settings, reviewed gate, ledger, TUI, contract checks | sensor, assessment and sandbox operations |
| Invoke | `yokai` from repo root | in your agent when wiring the verification bar |

Interactive Yokai proposes real sensor wrappers, smoke-runs them after command review, and saves automatically when all checks pass under Approve and test. It also reviews phase tier/strategy assessments in effort YAML. The helper skill is optional. See [sensors](/yokai/docs/sensors) and [wire your bar](/yokai/docs/sensors/wire-your-bar).

## When to use it

- You have (or will scaffold) a junji working folder and a machine-runnable gate under `.koi/sensors/`.
- You want unattended phase execution with objective verification, not chat-driven one-offs.
- You are ready to log the agent in (Claude, Cursor, OpenCode, or Codex). There is no separate driver login.

Connector: native ACP only (`claude`, `cursor`, `opencode`, `codex`).
